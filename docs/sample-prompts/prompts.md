## Project Setup & Configuration

### 1. Initial Test Project Setup

```
I need to set up unit testing for my Dataverse plugins. I'm using .NET 6 and xUnit. 
Can you create a test project with FakeXrmEasy configured?
```

### 2. Add Early-Bound Entities

```
My main plugin project uses early-bound entities generated by the Power Platform CLI. 
How do I configure my test project to use the same early-bound classes?
```

### 3. Switch from NUnit to xUnit

```
I have existing plugin tests using NUnit, but I want to migrate to xUnit. 
Can you help convert my test base class and update the test attributes?
```

### 4. Configure for .NET Framework

```
My plugins target .NET Framework 4.6.2. What version of FakeXrmEasy should I use, 
and how do I configure the middleware properly?
```

## Simple Plugin Testing

### 5. Test PreOperation Create Plugin

```
I have a plugin that sets the account number when an account is created. 
It runs PreOperation and generates a number like "ACC-20260413-1234". 
Can you write a unit test for this?
```

### 6. Test PostOperation Update Plugin

```
Test my ContactStatusPlugin that runs PostOperation on Update. When the contact's 
email changes, it should set a "verified" flag to false and create a verification task.
```

### 7. Test Delete Plugin with Validation

```
My plugin prevents deleting accounts that have open opportunities. It should throw 
InvalidPluginExecutionException with message "Cannot delete account with open opportunities." 
Write tests for both allowed and blocked deletions.
```

### 8. Test PreValidation Plugin

```
I have a PreValidation plugin that checks if the account name contains profanity. 
If found, it should throw an exception. How do I test both valid and invalid names?
```

## Tips for Using These Prompts

- **Be specific**: Include entity names, field names, and expected behavior
- **Mention context**: Specify .NET version, FakeXrmEasy version, test framework
- **Describe data**: Explain the test data needed (how many records, relationships, etc.)
- **State expectations**: Tell Claude what should be verified in assertions
- **Include constraints**: Mention performance requirements, validation rules, business logic
